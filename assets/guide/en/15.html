Multi-Agent and Harness: Iterate in a Controlled Loop Until Verification Passes

Companion to diagram #15 · Chapter 2 "Agent Design: Principles & Patterns"

Overview

When one agent runs out of context or time, several agents can split the work; but multi-agent value only pays off reliably inside a controlled loop (harness): tasks are split, executed and verified; failures go back with feedback until verification passes or the work is escalated to a human. "Harness" here means the engineering layer wrapped around the model: tools, permissions, context management, verification and stopping conditions.

Core Mechanisms

1. Orchestrator-workers. In Anthropic's pattern catalogue, a central LLM dynamically breaks down tasks, delegates them to worker LLMs and synthesizes their results. Unlike parallelization, subtasks are not predefined but decided by the orchestrator from the input — a good fit for coding tasks where you cannot predict which files need changes.

2. Anthropic's multi-agent research system. A lead agent plans the research process, then spawns parallel subagents to search simultaneously; each subagent explores a different aspect in its own context window and condenses the most important information for the lead. Published figures:

  • A system with Claude Opus 4 as lead and Claude Sonnet 4 subagents outperformed single-agent Claude Opus 4 by 90.2% on Anthropic's internal research eval.
  • In their analysis, token usage by itself explained 80% of performance variance, with the number of tool calls and model choice as the other two factors.
  • Agents use about 4× more tokens than chat interactions, and multi-agent systems about 15×.

3. Closed-loop verification. Anthropic stresses getting ground truth from the environment at each step. The evaluator-optimizer pattern has one LLM generate and another evaluate and give feedback in a loop, suited to tasks with clear evaluation criteria. In coding, the most reliable "evaluator" is tests, type checks and builds, not another model's subjective opinion.

4. State and compounding errors. The same article notes agents are stateful and errors compound; Anthropic uses "rainbow deployments" to shift traffic gradually so updates do not disrupt running agents, and its evaluation focuses on end states rather than turn-by-turn analysis.

Engineering Practice and Numbers

  • Tasks that suit multi-agent: heavy parallelization, information exceeding a single context, many tools. Anthropic states that domains requiring all agents to share the same context or involving many dependencies between agents are not a good fit today; most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time.
  • Cost accounting: roughly 15× the tokens of chat means only high-value tasks are worth it.
  • Minimal harness: task description with acceptance criteria, isolated execution environment, automated verification, maximum iterations, and rules for escalating to a human on failure.

Common Misconceptions

  • "More agents means faster." Parallel gains depend on whether the task splits into independent parts; coordination has its own cost.
  • "Having another model review is enough." Model review helps, but executable tests and checks give objective signals.
  • "Multi-agent is the default architecture." It is an upgrade for when one agent is not enough — see the decision tree in the next article.
