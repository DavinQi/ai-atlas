From Completion to AI IDEs: The Model Entered the Cursor, Then the Editor

Companion to diagram #19 · Chapter 3 "The Evolution of Programming"

Overview

AI's first step into developer tools was completion at the cursor: predicting the next line or block from the current file and cursor position. The second step was the AI IDE: the model no longer watches only the cursor but understands the whole project, edits across files, and explains and refactors code in chat. In both, the human still leads every change in the editor; AI is the "copilot".

Core Mechanisms

1. Code completion models. OpenAI's Codex paper introduced a GPT model fine-tuned on public GitHub code and noted that a production version powers GitHub Copilot. It also found repeated sampling an effective strategy: with 100 samples per problem, 70.2% of HumanEval problems were solved versus 28.8% with one sample. This explains why completion tools often offer several candidates.

2. From completion to chat and multi-file edits. AI IDEs add, beyond completion:

  • Chat: ask, explain and generate about selected code or the whole project.
  • Multi-file edits: one change spanning several files, presented as diffs for review.
  • Project-level context: index the codebase and retrieve relevant files on demand.

3. Persistent project rules. Keeping the model aligned with team conventions relies on rules files committed to the repo. Cursor's docs say rules provide persistent, reusable context at the prompt level; project rules live in .cursor/rules under version control; AGENTS.md is supported as a simpler alternative. AGENTS.md is positioned as "a README for agents", and its site says it is used by over 60k open-source projects. Claude Code reads CLAUDE.md.

4. Moving toward agents. GitHub Copilot's docs now cover agent mode in the IDE, a CLI, and a coding agent that works asynchronously in the cloud and can open or update PRs for human review. The line between completion tools and agent tools is blurring.

Key Papers and Milestones

  • 2021 Codex / HumanEval
  • June 29, 2021: Copilot technical preview, working especially well at first for Python, JavaScript, TypeScript, Ruby and Go
  • 2023 Copilot randomized controlled experiment: developers using Copilot implemented a JavaScript HTTP server 55.8% faster than the control group

Engineering Practice and Numbers

  • Productivity evidence depends on context: the 55.8% figure comes from a well-bounded experimental task. METR's 2025 randomized controlled trial found that 16 experienced open-source developers completing 246 tasks in mature projects they knew well took 19% longer when AI was allowed (mainly Cursor Pro with Claude 3.5/3.7 Sonnet); developers had expected a 24% speedup beforehand and still believed afterwards they had been 20% faster. The two studies do not contradict each other: gains depend heavily on task type, codebase familiarity and quality bar.
  • Commit rules files to Git so the team shares and reviews them.
  • Review AI-generated diffs like a colleague's PR, rather than accepting them directly.

Common Misconceptions

  • "Feeling faster means being faster." METR's study shows perception and measurement can point in opposite directions.
  • "Completion acceptance rate equals productivity." Acceptance rate measures usage, not delivery outcomes (see Chapter 4, "Metrics").
  • "The more rules, the better." Rules consume context; add them one by one for recurring problems.
