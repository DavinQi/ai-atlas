Guardrails and Choosing a Paradigm: If a Simple Solution Works, Skip Multi-Agent

Companion to diagram #16 · Chapter 2 "Agent Design: Principles & Patterns"

Overview

Agents read external content, call tools and execute code, so their risk surface is much larger than a plain chat app. This article covers two things: how to put guardrails on agents, and how to choose the right level of complexity. Both follow Anthropic's advice: find the simplest solution first, and add complexity only when it demonstrably improves outcomes.

Core Mechanisms

1. Prompt injection is the top risk. The OWASP Top 10 for LLM Applications 2025 lists prompt injection as LLM01. It has two forms:

  • Direct injection: user input directly alters model behavior.
  • Indirect injection: content the model ingests from external sources such as websites or files alters its behavior when interpreted.

Greshake et al. showed that LLM-integrated applications blur the line between data and instructions: attackers can plant prompts in data likely to be retrieved and exploit applications remotely, and processing retrieved prompts can act like arbitrary code execution. OWASP also acknowledges that, given how generative AI works, it is unclear whether fool-proof prevention exists, and RAG and fine-tuning do not fully mitigate it.

2. Defense in depth. OWASP's mitigations include:

  • Privilege control and least privilege: give the application its own API tokens and handle these functions in code rather than passing them to the model.
  • Human approval for high-risk actions: implement human-in-the-loop controls for privileged operations.
  • Segregate and identify external content: separate and clearly denote untrusted content to limit its influence.

The MCP spec likewise requires explicit user consent before invoking tools and treats tool descriptions from untrusted servers as untrusted.

3. The complexity ladder. Following Anthropic's patterns, from simple to complex:

  1. A single LLM call + retrieval + examples
  2. Fixed workflows: prompt chaining, routing, parallelization
  3. Dynamic workflows: orchestrator-workers, evaluator-optimizer
  4. A single autonomous agent
  5. Multi-agent systems

Key Papers and Milestones

  • 2023 Indirect prompt injection (Greshake et al.)
  • 2024 Anthropic, Building effective agents
  • 2025 OWASP LLM Top 10 (LLM01 Prompt Injection)
  • 2024 Agentless: on SWE-bench Lite, a simple three-phase "localize — repair — validate" process reached 32.00% resolution at about $0.70 per issue, beating all open-source agent approaches at the time

Engineering Practice and Numbers

Paradigm decision tree:

  • Can one call solve it? Yes → optimize the prompt and retrieval, and stop.
  • Are the steps fixed and predictable? Yes → use a workflow.
  • Are the steps unpredictable, needing autonomous decisions? Yes → single agent + tools + verification loop.
  • Does the task split into many independent subtasks exceeding one context? Yes → only then consider multi-agent.

Guardrail checklist:

  • Sandboxed execution; open network and filesystem only as needed.
  • Read-only first; writes and irreversible operations need human confirmation.
  • Treat all external content as data, not instructions.
  • Set maximum iterations and budget caps.
  • Log every tool call for auditing.

Common Misconceptions

  • "One line in the system prompt saying 'ignore external instructions' is enough." OWASP says there is no fool-proof prevention; permissions and architecture must be the backstop.
  • "Complex architecture means more capability." Agentless shows a simple process can be both better and cheaper on specific tasks.
  • "Security slows things down." Least privilege and human confirmation apply only to high-risk operations; routine low-risk tasks can be fully automated.
