Three Paradigms: Think While Acting, Plan Then Execute, Self-Correct Afterwards

Companion to diagram #12 · Chapter 2 "Agent Design: Principles & Patterns"

Overview

How an agent organizes "thinking" and "acting" determines its reliability, cost and interpretability. The diagram summarizes the three most common paradigms:

  • ReAct: think a step, act a step, observe, then think about the next step.
  • Plan-and-Solve / Plan-and-Execute: make a full plan first, then execute it step by step.
  • Reflection: evaluate the result afterwards and use verbal feedback to guide the next attempt.

They are not mutually exclusive; real systems often combine them.

Core Mechanisms

1. ReAct (Yao et al., 2022). The LLM generates reasoning traces and task-specific actions in an interleaved manner: reasoning helps the model induce, track and update action plans and handle exceptions; actions let it interact with knowledge bases or environments to gather more information. On HotpotQA question answering and Fever fact verification, ReAct — using a simple Wikipedia API — mitigated the hallucination and error propagation common in pure chain-of-thought reasoning, and produced trajectories that are more interpretable to humans than baselines.

Typical loop:

Thought → Action(tool, args) → Observation → Thought → … → Final Answer

2. Plan-and-Solve (Wang et al., 2023). Targeting the "missing-step" errors of zero-shot chain-of-thought, it first devises a plan that splits the task into subtasks, then carries them out; the extended PS+ adds more detailed instructions to reduce calculation errors. Across ten datasets with GPT-3, it consistently outperformed Zero-shot-CoT. The engineering Plan-and-Execute pattern follows the same idea: a planner emits a step list, an executor completes it step by step, re-planning when needed.

3. Reflexion (Shinn et al., 2023). Instead of updating weights, it reinforces agents through linguistic feedback: the agent verbally reflects on task feedback signals, stores the reflection text in an episodic memory buffer, and uses it to make better decisions in later trials. The paper reports 91% pass@1 on the HumanEval coding benchmark, above the 80% of GPT-4 at the time.

The related Self-Refine method has the same LLM act as generator, feedback provider and refiner, iteratively improving output; across 7 tasks it reports roughly 20% absolute improvement on average.

Engineering Practice and Numbers

Paradigm Fits Main cost
ReAct Unpredictable steps, explore as you go Many turns, may loop
Plan-and-Execute Clear structure, decomposable upfront Plan may go stale
Reflection Clear criteria, multiple attempts allowed Extra call per round
  • Reflection needs a reliable signal: Reflexion works well on coding partly because test results give objective feedback. Without an external signal, a model's self-assessment can be unreliable.
  • Mapping to Anthropic's patterns: Plan-and-Execute resembles "orchestrator-workers"; Reflection resembles "evaluator-optimizer", which works best when there are clear evaluation criteria and iteration provides measurable value.

Common Misconceptions

  • "ReAct is obsolete." Today's mainstream coding agents are still essentially "think — call tool — observe" loops, just with stronger models and more tools.
  • "The more detailed the plan, the better." Detailed plans break when the environment changes; re-planning must be supported.
  • "Self-reflection always improves results." Without external verification, reflection can reinforce wrong judgments.
