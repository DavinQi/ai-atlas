Orca: One Task per Worktree, One Agent per Worktree

Companion to diagram #30 · Chapter 5 "Multi-Agent Programming"

Overview

When several agents edit the same code at once, the first problem is stepping on each other: one agent's files get overwritten by another, and switching branches interrupts running tasks. Git worktree is the infrastructure that solves this, and Orca is a multi-agent development workbench built around it. Orca's docs describe it as a desktop IDE for running multiple AI coding agents side by side, where each task gets its own git worktree, its own agent terminal and its own browser tab.

Core Mechanisms

1. Git worktree. Git's docs explain that a repository can support multiple working trees, allowing more than one branch to be checked out at a time; new working trees are called "linked worktrees", as opposed to the main worktree created by git init or git clone. All worktrees share the repository's objects and history but each has its own working directory and checked-out branch.

git worktree add ../fix-payment -b fix-payment
git worktree list
git worktree remove ../fix-payment

2. Orca's model. The docs compress the workflow to: add a repo → open a workspace (worktree) → pick an agent → split panes → review changes → commit. Key points:

  • No bundled model: it runs the Claude Code, Codex, Cursor CLI, OpenCode and so on that you already have, with your own subscriptions.
  • Every worktree is a real git worktree; you can enter the directory and use native git at any time.
  • Runs locally on your desktop by default; remote compute uses machines you control (SSH, self-hosted servers or cloud VMs).

3. Making a new worktree productive immediately. A new worktree is clean code checked out from Git, so untracked .env files and dependency directories aren't there. The X developer cited earlier explains that Orca can be configured to copy some files into each copy (e.g. .env) and share some directories (e.g. dependency packages).

4. Shared rules. Project rules rely on files agents read themselves: Claude Code reads CLAUDE.md, Codex reads AGENTS.md. They must be committed to Git, or agents in new worktrees won't see them.

Engineering Practice and Numbers

  • Notifications and review: per the developer above, Orca pops a notification when an agent goes from working to idle; the changes view supports line-by-line annotations sent back to the agent in one batch, and can mark which lines AI wrote.
  • Task naming: one worktree per clear task and branch, for easy cleanup.
  • Delete when done: remove losing or finished worktrees and their branches promptly.
  • Where it fits: the developer admits that if you use one vendor's agent and do one thing at a time, Orca won't help much and the official client is enough; its value scales with the number of agents running at once and the volume of changes to accept.

Common Misconceptions

  • "Opening a few more terminals is the same." It can be, but you must solve missing dependencies, tracking and review yourself.
  • "Worktrees are fully isolated." They share repository history and the object store; runtime resources such as ports, databases and external services can still conflict.
  • "Orca is a model or hosted service." The docs state explicitly it is neither a model nor a hosted VPS product.
