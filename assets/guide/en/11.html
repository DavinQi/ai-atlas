Agent Components: LLM + Planning + Memory + Tools, Looping on Environment Feedback

Companion to diagram #11 · Chapter 2 "Agent Design: Principles & Patterns"

Overview

There is no single agreed definition of "agent". In Building effective agents, Anthropic calls every LLM-based automation an agentic system and draws one key distinction: workflows orchestrate LLMs and tools through predefined code paths, while agents let the LLM dynamically direct its own process and tool use, keeping control over how it accomplishes the task.

Lilian Weng's 2023 survey LLM Powered Autonomous Agents gives a widely cited framework: the LLM acts as the agent's "brain", complemented by three key components — Planning, Memory and Tool Use.

Core Mechanisms

1. Planning. Break a large task into manageable subgoals, and use self-reflection to learn from past actions and correct mistakes.

2. Memory. Weng's split:

  • Short-term memory: everything in context (in-context learning), bounded by the context window.
  • Long-term memory: an external vector store with fast retrieval to retain and recall information over long periods.

3. Tools. Call external APIs for information missing from the weights: live data, code execution, private databases. Toolformer showed a model can teach itself, in a self-supervised way, when and how to call APIs; CodeAct proposed executable Python code as a unified action space, reporting up to 20% higher success rate than JSON/text actions on its benchmark.

4. The environment feedback loop. Anthropic stresses that during execution an agent must get "ground truth" from the environment at each step (tool results, code execution) to assess progress, and may pause for human feedback at checkpoints or when blocked; stopping conditions such as a maximum number of iterations should be set. Their conclusion: agents are usually simple to implement — they are essentially LLMs using tools based on environmental feedback in a loop — so designing the toolset and its documentation is crucial.

The CoALA framework gives a more formal, cognitive-science view: modular memory components, a structured action space for interacting with internal memory and the external environment, and a generalized decision process for choosing actions.

Engineering Practice and Numbers

  • Start with the simplest solution: Anthropic advises finding the simplest solution and adding complexity only when needed; many applications only need a single optimized LLM call with retrieval and in-context examples. Agentic systems typically trade latency and cost for better task performance.
  • Use frameworks with care: they add abstraction layers that obscure the underlying prompts and responses and make debugging harder. Start by calling LLM APIs directly — many patterns take a few lines of code.
  • Three principles: keep the design simple; make the agent's planning steps explicit for transparency; carefully craft the agent-computer interface (ACI) through thorough tool documentation and testing. SWE-agent likewise showed that interfaces designed specifically for agents significantly improve performance on software-engineering tasks.

Common Misconceptions

  • "An agent is a chatbot with tools." The real difference is who decides control flow: code in a workflow, the model in an agent.
  • "More autonomy is always better." Autonomy means higher cost and compounding errors; Anthropic recommends extensive testing in sandboxes with guardrails.
  • "Memory means stuffing all history into context." Context is short-term memory; long-term memory needs external storage and retrieval.
