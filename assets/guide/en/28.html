A 7-Day Roadmap: What Individuals and Small Teams Can Start This Week

Companion to diagram #28 · Chapter 4 "AI Coding Today"

Overview

The previous articles covered principles; this one compresses them into a checklist an individual or small team can execute in a week. The roadmap is the presenter's own suggestion, distilled from Alibaba's handbook, not any company's official process. The handbook's core advice for starting teams: you don't need to build a complete system at once — first build a project map, standardize complex requirements, provide verifiable feedback, and connect the production fact chain to form a basic loop.

Core Mechanisms

Day 1: Pick a real small task and run it end to end. Choose a well-bounded bug or small feature that has tests, let a coding agent complete it, and record the time and problems encountered.

Day 2: Write a project rules file. In the repo root write AGENTS.md or CLAUDE.md: tech stack, directory layout, build and test commands, prohibitions, operations that require stopping to ask (database migrations, secrets, production). Commit it to Git.

Day 3: Add a project map. Responsibilities, entry points and dependencies of key modules. Let the agent draft it and a human proofread.

Day 4: Make verification one command. Compile, type check, lint and unit tests in a single command, recorded in the rules file so the agent runs it after every change.

Day 5: Do a medium requirement with a Spec. Let the agent ask clarifying questions first, write constraints, acceptance criteria and non-goals into the Spec, then implement.

Day 6: Build review habits. Small MRs; check test results and core logic first; send all feedback to the agent in one batch for rework.

Day 7: Retrospect and capture. Where did the agent repeatedly go wrong? Add a rule. Which process repeated three or more times? Turn it into a Skill. Record delivery cycle and rework count as a baseline.

Key Papers and Milestones

  • Anthropic, Building effective agents: start with the simplest solution and add complexity only when it demonstrably helps
  • Alibaba's AI Native R&D Paradigm Practice Handbook: four basic loops for starting teams
  • AGENTS.md: an open format for agent instruction files

Engineering Practice and Numbers

  • Add rules gradually: the X developer sharing Orca usage advises not writing dozens of rules at once — add one when the agent repeatedly makes the same mistake; his example rules include "existing tests may only be added to, never modified or deleted" and "stop and ask me before touching database migrations, payment keys or production".
  • The rule of three: another developer suggests that once a process repeats more than three times, have the agent turn it into a Skill.
  • Measure the baseline first: without Day 1 vs Day 7 data you cannot tell whether productivity really improved (see the METR study in the previous article).
  • Allow parallel exploration: the handbook notes that while methods are immature, letting members explore separately and share regularly finds effective paths better than standardizing too early; converge on a unified workflow once practice stabilizes.

Common Misconceptions

  • "Buy the most expensive tools and go multi-agent first." Until a single agent + rules + verification loop works, multi-agent only amplifies chaos.
  • "You'll see 10× gains in a week." The week's goal is a working loop and a baseline, not results.
  • "Once the rules file is written, leave it alone." It should evolve with the project and team experience.
