Why Multi-Agent: Trade Parallelism for Time, Paid in Tokens and Review

Companion to diagram #29 · Chapter 5 "Multi-Agent Programming"

Overview

A single coding agent does one thing at a time. When a task splits into independent parts, running several agents at once trades parallelism for time. But parallelism isn't free: every agent consumes tokens and every output needs human review. The core question of multi-agent programming is when this trade pays off.

Core Mechanisms

1. Gains come from parallelism and context isolation. In Anthropic's multi-agent research system, subagents explore different aspects in parallel in their own context windows and condense the most important information for the lead agent. Their internal research eval showed the multi-agent system outperforming a single agent by 90.2%; for complex queries, parallelization cut research time by up to 90%.

2. The cost is tokens. The same article says agents use about 4× the tokens of chat and multi-agent systems about 15×; token usage by itself explained 80% of performance variance.

3. Coding tasks have limited parallelism. Anthropic states that most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating in real time. Tasks requiring all agents to share the same context, or with many dependencies between agents, are not a good fit today.

4. Human review is the new bottleneck. The X developer sharing Orca usage summarized four things you hit after running many agents: new copies lack dependencies and secrets and won't run; you can't keep track of which agent is working and which is waiting for confirmation; you can't review it all — generation keeps getting faster and acceptance becomes the bottleneck; and you get locked into one vendor's quota.

Key Papers and Milestones

  • 2023 MetaGPT, ChatDev, AutoGen: early multi-agent software development frameworks
  • 2023 Multiagent debate: multiple model instances debating over rounds improves reasoning and factuality
  • 2025 Anthropic's multi-agent research system
  • Subagents in Claude Code / Codex / Cursor: each works in its own context window and returns results to the main agent

Engineering Practice and Numbers

When multi-agent is worth it:

  • Independent subtasks: different modules, different pages, separate frontend/backend reviews.
  • Mistakes are costly, so comparing multiple solutions is worthwhile (see the "race" approach).
  • Information exceeds one context: large-scale research, codebase exploration.

When not to:

  • Small changes, copy edits.
  • Highly coupled changes that must be coordinated in one context.
  • No automated verification yet, and review capacity can't keep up.

Do the math: three agents in parallel means three quotas. The developer above quotes a review: what you save is retry time, but you still pay three times; so only race where mistakes are painful, such as payments, permissions and data migrations.

Common Misconceptions

  • "Multi-agent is always faster." It depends on how parallelizable the task is; coordination and review both cost.
  • "Tokens are cheap, no need to count." 15× consumption adds up at scale.
  • "More agents means reading less code." More output needs more automated verification and better review tools.
