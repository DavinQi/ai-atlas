Amdahl's Law: Speeding Up Only Coding Caps the Overall Gain

Companion to diagram #22 · Chapter 4 "AI Coding Today"

Overview

In 1967, in a paper on parallel computing, Gene Amdahl stated what became known as Amdahl's law: the overall speedup of a system is limited by the part that cannot be sped up. Applied to software delivery, the conclusion is just as direct — if coding is only a small part of the delivery cycle, then even if AI reduced coding time to zero, overall delivery would not get much faster.

Core Mechanisms

Let coding be a fraction p of the whole delivery cycle, and let AI speed up coding by a factor s. The overall speedup is:

S=(1−p)+sp​1​

As s→∞ (coding time approaches zero), the ceiling is:

Smax​=1−p1​

Some numbers (computed from the formula):

Coding share p Coding 10× faster Coding time zero
20% 1.22× 1.25×
30% 1.37× 1.43×
50% 1.82× 2×

In other words, if coding is 30% of the cycle, however fast coding gets, overall delivery is at most about 43% faster.

Engineering Practice and Numbers

Data from the front line. Alibaba's handbook records:

  • Rough internal estimates put code generation itself at only 20%–30% of the whole development chain, or even less. For one consumer-facing user-flow change, coding and local verification might take an hour, but after multiple internal platforms, release processes and environment constraints — and a change freeze, if one hits — it could still take weeks from code complete to live.
  • An "anomalous figure": auto-fixed bugs exceeded 60%, yet the same-day bug resolution rate rose only from 53% to at most 63%, because triggering depended on people and checking depended on people. The handbook calls this Amdahl's law in real life: single-point automation is high, but end-to-end throughput does not move because human nodes still block the chain.

What to do:

  1. Measure before optimizing: map the value stream from request to production and mark the time and waiting at each step.
  2. Point AI at the bottleneck: requirements clarification, testing and verification, environment setup, release approval and troubleshooting often deserve optimization more than coding does.
  3. Remove "a human must trigger it" choke points: the handbook team's next step is having execution nodes discover pending work themselves and be routed by a scheduling layer, instead of waiting for a person to start them.

Common Misconceptions

  • "If AI writes code 10× faster, the team is 10× faster." Amdahl's law says the ceiling is set by the part that cannot be accelerated.
  • "Steps outside coding are someone else's problem." End-to-end delivery is the value; local optima are not global optima.
  • "The law is outdated." It describes system structure and does not expire with technology; the more thoroughly coding is solved, the more other steps become the new bottleneck.
