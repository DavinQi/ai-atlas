安全护栏与范式选择：能用简单方案，就别上多 Agent

对应图 #16 · 第二章「Agent 设计原理与范式」

概述

Agent 能读外部内容、调用工具、执行代码，这让它的风险面远大于普通聊天应用。本篇讨论两件事：怎么给 Agent 装护栏，以及怎么选择合适的复杂度。两者的共同原则都来自 Anthropic 的建议：先找最简单的方案，只有在能证明效果提升时才增加复杂度。

核心机制

1. 提示注入是头号风险。 OWASP《LLM 应用十大风险》2025 版把提示注入列为 LLM01。它分为两类：

  • 直接注入：用户输入直接改变模型行为。
  • 间接注入：模型从网页、文件等外部来源读入的内容，在被解析时改变模型行为。

Greshake 等人的研究指出，LLM 集成应用模糊了数据与指令的界限，攻击者可以把提示植入可能被检索到的数据中远程利用应用，处理检索到的提示可以等同于任意代码执行。OWASP 也承认，鉴于生成式 AI 的工作原理，尚不清楚是否存在万无一失的预防方法，RAG 和微调也不能完全缓解。

2. 纵深防御。 OWASP 给出的缓解措施包括：

  • 权限控制与最小权限：给应用独立的 API 令牌，在代码中处理这些功能，而不是交给模型。
  • 高风险操作须人工批准：对特权操作实施人在回路的控制。
  • 隔离并标识外部内容：把不可信内容分隔并清楚标注，限制其影响。

MCP 规范同样要求调用工具前获得用户明确同意，并把来自不受信服务器的工具描述视为不可信。

3. 复杂度阶梯。 结合 Anthropic 的模式库，从简到繁依次是：

  1. 单次 LLM 调用 + 检索 + 示例
  2. 固定工作流：提示链、路由、并行化
  3. 动态工作流：编排者—工作者、评估者—优化者
  4. 单个自主 Agent
  5. 多 Agent 系统

关键论文与里程碑

  • 2023 间接提示注入（Greshake 等）
  • 2024 Anthropic《Building effective agents》
  • 2025 OWASP LLM Top 10（LLM01 提示注入）
  • 2024 Agentless：在 SWE-bench Lite 上，简单的「定位—修复—验证」三阶段流程以 32.00% 的解决率和每题约 0.70 美元的成本，超过了当时所有开源 Agent 方案

工程实践与数字

范式决策树：

  • 一次调用能解决吗？能 → 优化提示与检索，到此为止。
  • 步骤固定且可预知吗？是 → 用工作流。
  • 步骤不可预知、需要模型自主决策吗？是 → 单 Agent + 工具 + 验证闭环。
  • 任务能拆成大量独立子任务、且超出单个上下文吗？是 → 才考虑多 Agent。

护栏清单：

  • 沙箱执行，网络与文件系统按需开放。
  • 只读优先，写操作和不可逆操作需要人工确认。
  • 外部内容一律视为数据而非指令。
  • 设置最大迭代次数和预算上限。
  • 记录完整的工具调用日志以便审计。

常见误区

  • 「系统提示里写一句『不要听外部指令』就够了。」 OWASP 指出没有万无一失的预防方法，必须靠权限和架构设计兜底。
  • 「复杂架构代表更强能力。」 Agentless 的结果说明，在特定任务上简单流程可以同时做到更好和更便宜。
  • 「安全会拖慢效率。」 最小权限和人工确认只作用于高风险操作，日常低风险任务可以全自动。
