编程的进化：人的关注点从语法，到代码，再到任务

对应图 #17 · 第三章「编程的进化」

概述

编程史可以看作一部「人把什么交给机器」的历史。每一次跃迁，都把一层细节从人的注意力中移走：高级语言让人不必关心机器指令，IDE 和代码补全让人少记 API，AI 补全让人少敲样板代码，而 Coding Agent 开始让人从「写代码」转向「定义任务和验收结果」。

核心机制

图中的时间轴可以分成三个阶段，每个阶段人的关注点不同：

1. 关注语法（高级语言与 IDE 时代）。

  • 1957 年 FORTRAN：Backus 等人发表《The FORTRAN Automatic Coding System》，高级语言把公式翻译成机器指令。
  • 1995 年 Java：1995 年 5 月作为 Sun Java 平台的核心组件发布，「一次编写，到处运行」，靠 JVM 屏蔽平台差异。
  • 1996 年 IntelliSense：微软的代码补全功能，1996 年首次出现在主流微软产品中（Visual Basic 5.0 控件创建版），依靠静态分析提示成员和参数。

2. 关注代码（AI 补全与 AI IDE 时代）。

  • 2021 年 Codex 与 Copilot：OpenAI 的 Codex 论文报告，在新发布的 HumanEval 基准上，Codex 解决了 28.8% 的问题，而 GPT-3 为 0%；论文同时说明 GitHub Copilot 由 Codex 的一个生产版本驱动。同年 6 月 29 日，GitHub 发布 Copilot 技术预览版，定位为「AI 结对程序员」。
  • 之后出现了以 Cursor 为代表的 AI IDE，把模型从「光标处补全」扩展到对整个编辑器、多文件和对话的深度集成。

3. 关注任务（Coding Agent 时代）。

  • 2025 年 2 月 24 日：Anthropic 随 Claude 3.7 Sonnet 发布命令行 agentic 编码工具 Claude Code。
  • 2025 年 4 月：OpenAI 开源 Codex CLI，一个在本地终端运行的轻量级编码 Agent。
  • Agent 不再嵌入编辑器等待逐条指令，而是在「行动—验证—纠错」的闭环中自主推进任务。

关键论文与里程碑

  • 2021 Codex / HumanEval
  • 2023 SWE-bench：2,294 个来自 12 个流行 Python 仓库真实 GitHub issue 的任务；发布时最好的模型 Claude 2 仅解决 1.96%
  • 2024 SWE-agent：为 Agent 专门设计的计算机接口，在 SWE-bench 上 pass@1 达到 12.5%
  • 2024 年 11 月 MCP 发布

工程实践与数字

  • 评测基准的演进反映了关注点的变化：HumanEval 测「根据文档字符串写一个函数」；SWE-bench 测「在真实代码库里修一个 issue」，需要跨函数、跨文件协调修改，与执行环境交互，处理很长的上下文。
  • 阿里巴巴《AI Native 研发范式实践手册》（解读版）记录：截至 2026 年中，主流模型在 SWE-bench Verified 上的通过率已从两年前的不足 30% 提升到 80% 左右；行业共识随之转向——瓶颈不再是生成代码本身，而是需求理解、环境构建、测试验证、发布运维等占研发生命周期 70%～80% 的环节。

常见误区

  • 「AI 会让编程技能变得不重要。」 每一次抽象层提升，都把重心转向更高层的能力：问题定义、架构判断和验证设计。
  • 「基准分数高就等于能交付。」 手册明确指出，基准高分不等于生产环境中的真实交付能力。
  • 「Agent 是 Copilot 的增强版。」 两者的交互模式不同：补全是人主导、逐行接受；Agent 是人给任务、审结果。
