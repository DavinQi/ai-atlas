数据与分词：文本先切成 token，再映射成向量

对应图 #4 · 第一章「大模型如何训练」

概述

模型从不直接「看」文字。原始文本先经过清洗与去重，再由分词器（tokenizer）切成离散 token，每个 token 对应一个整数 id，最后通过嵌入矩阵（embedding）查表变成向量，进入 Transformer。数据质量决定模型上限，分词方式则决定同样的算力能「读」多少文本、各语言的成本是否公平。

核心机制

1. 数据管线。 以 FineWeb 为例：它从 96 个 Common Crawl 快照中构建出 15T token 的数据集，并对去重和过滤策略做了系统消融；从中筛出的 1.3T token 教育类子集 FineWeb-Edu，在 MMLU、ARC 等知识与推理基准上带来显著提升。典型步骤包括：文本抽取 → 语言识别 → 启发式与模型打分的质量过滤 → MinHash 等去重 → 隐私信息与有害内容过滤。

2. 子词分词（BPE）。 Sennrich 等人把字节对编码（BPE）引入神经机器翻译：从字符（或字节）开始，反复把语料中出现频率最高的相邻符号对合并成新符号，直到词表达到目标大小。这样常见词是一个 token，罕见词被拆成若干子词，不存在「未登录词」。SentencePiece 把原始文本（含空格）直接当作序列处理，不依赖语言相关的预分词，适合中文等不以空格分词的语言。

Karpathy 在讲解中强调：分词器是 LLM 流水线中完全独立的一个阶段，有自己的训练集和训练算法（BPE），训练完后提供 encode() 和 decode() 两个函数。

3. 嵌入。 设词表大小为 V、隐藏维度为 d，嵌入矩阵 E∈RV×d，token id i 的向量就是 E 的第 i 行。位置信息由位置编码注入，现代模型多用 RoPE，它对 query/key 按位置施加旋转，使注意力分数只依赖相对位置。

工程实践与数字

Llama 3 报告给出了词表设计的直接证据：

  • 词表 128K：100K 来自 tiktoken，另加 28K 非英语 token。
  • 相比 Llama 2 的分词器，英文样本上的压缩率从每 token 3.17 个字符提高到 3.94 个，作者指出这让模型在同样的训练算力下能「读」更多文本。
  • 增加 28K 非英语 token 改善了这些语言的压缩率和下游表现，对英文分词没有影响。
  • RoPE 基频提高到 500,000 以支持更长上下文。

工程含义：

  • API 计费按 token，同样的中文内容在不同模型上 token 数可能差很多，估算成本前应用对应分词器实测。
  • 词表越大，嵌入层和输出层参数越多，但序列越短，注意力的计算和 KV Cache 都更省。
  • 数据去重同时影响质量和评测可信度：训练集若混入评测题，分数会虚高。

常见误区

  • 「模型按字/词理解文本。」 模型看到的是子词 id。数字、拼写、字符计数类任务出错，很多源于分词粒度。
  • 「数据越多越好。」 FineWeb-Edu 说明经过筛选的较小子集可以明显优于更大的未筛选数据。
  • 「分词器可以随便换。」 嵌入矩阵与词表一一对应，换分词器通常意味着重新训练或大量继续训练。
