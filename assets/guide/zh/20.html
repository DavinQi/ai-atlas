Coding Agent：人给任务、审 PR，Agent 自己跑完闭环

对应图 #20 · 第三章「编程的进化」

概述

Coding Agent 把开发者从「逐行指挥」中解放出来：人描述任务，Agent 自己读代码、改文件、跑命令、看结果、修正错误，最后交付一个可审阅的变更。Claude Code 文档的定义是：一个能读取代码库、编辑文件、运行命令并与开发工具集成的 agentic 编码工具，可在终端、IDE、桌面应用和浏览器中使用。OpenAI 的 Codex CLI 则是一个在本地终端运行的编码 Agent，另有云端版本。

核心机制

1. 闭环。 一次任务的典型循环：

理解任务 → 搜索与阅读代码 → 制定计划
→ 修改文件 → 运行构建 / 测试 / lint
→ 读取输出 → 修正 → … → 全部通过
→ 提交 / 开 PR → 人审阅

这正是 Anthropic 所说的「LLM 在循环中根据环境反馈使用工具」。环境反馈（编译错误、测试失败、日志）是 Agent 能自我纠错的根本原因。

2. 即时检索上下文。 Anthropic 介绍，Claude Code 会把 CLAUDE.md 等文件直接放入上下文，同时用 glob、grep 等原语即时浏览环境、检索文件，绕开了索引过期和复杂语法树的问题。

3. 子 Agent 与上下文隔离。 Claude Code 的每个子 Agent 都在自己的上下文窗口中运行，有自定义的系统提示、特定的工具权限和独立的权限设置。例如在计划模式下，它把代码库调研委派给只读的 Plan 子 Agent，让探索输出留在独立的上下文中。Codex 和 Cursor 也都支持子 Agent：并行派生专门的 Agent，再把结果汇总回来。

4. 权限与沙箱。 Agent 能执行命令，就必须控制它能做什么：哪些命令自动允许、哪些需要确认、能否访问网络、能写哪些目录。

工程实践与数字

  • 人的角色转为定义任务和审阅结果。一位开发者在 X 上分享的工作流很典型：先把 PRD、会议纪要等材料交给 Agent，通过连续追问对齐需求，把结论沉淀到 Spec 或 CONTEXT.md；复杂需求拆成可独立验收的 Issue，只有能独立推进的部分才交给子 Agent 在不同 worktree 中并行开发；编码 Agent 先写测试，再引入其他 Agent 做交叉审查；人工 Review 之前跑端到端测试，并保持每个 MR 足够小。
  • 给 Agent 可执行的验证：测试、类型检查、lint、构建。没有这些，Agent 只能靠「觉得对」。
  • 规则文件写清技术栈、禁止事项和需要停下来请示的操作（如数据库迁移、生产环境、密钥）。

常见误区

  • 「Agent 交付的就能直接合并。」 Agent 会过度设计，也会在测试不足时宣布完成，人审阅仍不可少。
  • 「上下文越多越好。」 子 Agent 的意义之一正是隔离上下文，让主会话保持干净。
  • 「Agent 能替代测试。」 恰恰相反，Agent 越自主，越依赖自动化测试。
