从补全到 AI IDE：模型先进了光标，再进了编辑器

对应图 #19 · 第三章「编程的进化」

概述

AI 进入开发工具的第一步是光标处的补全：根据当前文件和光标位置，预测接下来的一行或一段代码。第二步是AI IDE：模型不再只盯着光标，而是可以理解整个项目、跨文件修改、在对话中解释和重构代码。两者的共同点是人仍然在编辑器里主导每一次修改，AI 是「副驾驶」。

核心机制

1. 代码补全模型。 OpenAI 的 Codex 论文介绍了在 GitHub 公开代码上微调的 GPT 模型，并说明其生产版本驱动 GitHub Copilot。论文同时发现，重复采样是获得正确解的有效策略：每题采样 100 次时，能解决 70.2% 的 HumanEval 问题，而单次采样为 28.8%。这也解释了补全工具为什么常常提供多个候选。

2. 从补全到对话与多文件编辑。 AI IDE 在补全之外加入：

  • 对话：针对选中代码或整个项目提问、解释、生成。
  • 多文件编辑：一次修改涉及多个文件，以 diff 形式呈现给人审阅。
  • 项目级上下文：索引代码库，按需检索相关文件。

3. 持久化的项目规则。 让模型持续遵守团队约定，靠的是写进仓库的规则文件。Cursor 文档说明：规则在提示层提供持久、可复用的上下文；项目规则存放在 .cursor/rules 中，纳入版本控制；也支持 AGENTS.md 作为更简单的替代。AGENTS.md 被定位为「给 Agent 看的 README」，官网称已有超过 6 万个开源项目使用。Claude Code 则读取 CLAUDE.md。

4. 走向 Agent。 GitHub Copilot 的文档如今已覆盖 IDE 中的 agent 模式、CLI 以及在云端异步工作、可以直接开启或更新 PR 供人审阅的编码 Agent。补全工具和 Agent 工具的边界正在模糊。

关键论文与里程碑

  • 2021 Codex / HumanEval
  • 2021 年 6 月 29 日 Copilot 技术预览版：首批对 Python、JavaScript、TypeScript、Ruby 和 Go 效果尤其好
  • 2023 Copilot 随机对照实验：使用 Copilot 的开发者完成一个 JavaScript HTTP 服务器的速度比对照组快 55.8%

工程实践与数字

  • 生产力证据要看场景：上述 55.8% 来自一个边界清晰的实验任务。METR 2025 年的随机对照试验发现，16 位经验丰富的开源开发者在自己熟悉的成熟项目中完成 246 个任务，允许使用 AI（主要是 Cursor Pro 和 Claude 3.5/3.7 Sonnet）时完成时间反而增加了 19%；而开发者事前预计会缩短 24%，事后仍认为缩短了 20%。两项研究并不矛盾：收益高度依赖任务类型、代码库熟悉度和质量标准。
  • 规则文件要提交到 Git，团队共享且可审查。
  • 把 AI 生成的 diff 当作同事的 PR 来审，而不是直接接受。

常见误区

  • 「感觉更快就是更快。」 METR 的研究显示主观感受和实际测量可能相反。
  • 「补全接受率等于生产力。」 接受率衡量的是使用量，不是交付结果（见第四章「度量」）。
  • 「规则写得越多越好。」 规则占用上下文，应针对反复出现的问题逐条补充。
