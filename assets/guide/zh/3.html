训练全景：预训练学会语言，后训练学会听指令与推理

对应图 #3 · 第一章「大模型如何训练」

概述

今天的通用大语言模型（LLM）几乎都遵循同一条流水线：数据准备 → 分词（tokenize）→ 预训练（pretraining）→ 后训练（post-training）→ 推理部署（inference）。预训练在数万亿 token 的通用语料上做「预测下一个 token」的自监督学习，模型由此获得语言、知识和一定的推理能力；后训练用少得多的数据，通过监督微调（SFT）、基于偏好的优化（RLHF / DPO）以及可验证奖励的强化学习（RLVR），把一个「会续写」的基座模型变成「会听指令、会推理、守规矩」的助手。

把这条线理解清楚，对架构师有直接价值：它决定了哪些能力是「买来的」（基座里已有），哪些能力能通过微调或提示「调出来」，以及成本主要花在哪里。

核心机制

1. 预训练目标。 给定 token 序列 x1​,…,xT​，最小化自回归交叉熵：

L(θ)=−t=1∑T​logpθ​(xt​∣x<t​)

GPT-3 论文表明，只用这一目标、把规模推到 1750 亿参数，模型就能在不更新参数的情况下通过 few-shot 提示完成大量任务。

2. 规模定律。 Kaplan 等人发现 loss 随参数量、数据量和算力呈幂律下降；Chinchilla 进一步指出，在固定算力下，参数量和训练 token 数应同比例扩大。这决定了「模型多大、喂多少数据」这一首要工程决策（详见本章第 4 篇）。

3. 后训练。 InstructGPT 给出了经典三步：人写示范做 SFT → 人工对输出排序训练奖励模型 → 用 PPO 做强化学习。之后 DPO 把偏好优化化简为一个分类式损失；DeepSeek-R1 则证明在数学、代码等可自动验证的任务上，纯强化学习就能激发长链推理。

4. 推理。 部署时分为 Prefill（一次性处理整段提示）和 Decode（逐 token 生成）两个阶段，KV Cache 管理和批处理调度决定吞吐与成本（详见第 6 篇）。

关键论文与里程碑

  • 2017 Transformer：完全基于注意力的架构，成为后续所有 LLM 的骨架。
  • 2020 GPT-3：175B 参数，展示 in-context learning。
  • 2020 / 2022 Scaling Laws：从「越大越好」到「算力最优配比」。
  • 2022 InstructGPT：在其人工评测中，1.3B 的 InstructGPT 输出比 175B 的 GPT-3 更受偏好，参数少 100 倍。
  • 2023 DPO：无需显式奖励模型和在线采样的偏好优化。
  • 2024 Llama 3：公开的旗舰级训练报告，405B 稠密模型、15.6T token。
  • 2025 DeepSeek-R1：强化学习驱动的推理模型。

工程实践与数字

下面的数字均来自原始报告：

  • Llama 3 405B：15.6T 文本 token，预训练算力 3.8×1025 FLOPs，最多使用 16K 块 H100。
  • DeepSeek-V3：671B 总参数、每 token 激活 37B，14.8T token，完整训练 2.788M H800 GPU 小时。
  • InstructGPT：后训练的数据和算力远小于预训练，但对「可用性」的提升极大。LIMA 的实验也显示，仅用 1000 条精选样本做 SFT 就能得到很强的对话表现，作者据此提出「知识几乎全部来自预训练」的假设。

经验结论：能力上限主要由预训练（数据 + 规模）决定，后训练决定「怎么用这些能力」。 对企业而言，绝大多数场景应选用现成基座或指令模型，再用提示工程、RAG 或轻量微调适配，而不是从头预训练。

常见误区

  • 「微调能教会模型新知识。」 少量 SFT 主要改变输出风格和格式；要注入大量新事实，RAG 或继续预训练通常更可靠。
  • 「RLHF 就是真正的强化学习。」 Karpathy 指出 RLHF「只勉强算 RL」：奖励模型只是人类偏好的近似，优化过度就会被「钻空子」。可验证奖励（RLVR）正是为了解决这一点。
  • 「训练完就结束了。」 推理部署的累计成本经常超过训练，架构选型（MoE、GQA）往往是为推理服务。
