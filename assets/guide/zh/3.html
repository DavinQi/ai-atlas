训练全景：预训练学会语言，后训练学会听指令与推理

对应图 #3 · 第一章「大模型如何训练」

图 #3 把一个聊天助手的诞生画成一条流水线：数据 → 预训练 → 基座模型 → 后训练（SFT、偏好对齐、可验证奖励的强化学习）→ 评测 → 推理部署。看上去像工厂里的工序表，但每一段解决的问题完全不同。这篇文章不逐格解释方框，而是跟着一个问题走完全程：一个只会「预测下一个 token」的程序，是怎样一步步变成会回答、会推理、守规矩的助手的？ 每一步它多学会了什么，又留下了什么短板？

一、起点：一张「下一个 token」的概率表

先玩一个填空游戏。「床前明月____」，几乎所有人都会填「光」；「今天天气很____」，答案就不唯一了：好、热、冷、不错……但很少有人会填「贵」。把各种可能按把握大小列出来，就是一张概率表。

语言模型做的就是这件事：给定前文，输出「下一个 token」的概率分布。token 是模型处理文字的最小单位，可能是一个字，也可能是常一起出现的几个字（下一篇专门讲）。写一整段话，只是把这个动作循环起来：从概率表里选一个 token 接到前文后面，再把新的前文交给模型预测下一个。

训练的目标也因此非常朴素。给定一段真实文本 x1​,…,xT​，让模型在每个位置给「真实的下一个 token」尽量高的概率，也就是最小化交叉熵：

L(θ)=−t=1∑T​logpθ​(xt​∣x<t​)

这个式子可以用信息论来读。香农把一个结果的信息量定义为 −log2​p：概率越小，出现时越「出乎意料」，信息量越大。交叉熵就是「按模型的估计去编码真实文本，平均每个 token 要花多少 bit」。模型猜得越准，花的 bit 越少；如果模型的概率和人写作时的真实概率完全一致，交叉熵就降到文本本身的熵，再也压不下去。香农在 1951 年让受试者逐字母猜英文，估算出英文每个字符的熵只有约 0.6～1.3 bit，而且上下文看得越长，下一个字母越好猜。

为什么这么朴素的目标能学出「智能」？ 因为要把下一个 token 猜准，光记住字词搭配远远不够：「法国的首都是____」需要知识；「小明比小红高，小红比小刚高，最矮的是____」需要推理；「他打开冰箱发现牛奶过期了，皱着眉把它____」需要常识。人写下的文字里藏着知识、逻辑和意图，模型想压低交叉熵，就不得不把这些规律学进去。这是一个有用的视角，而不是定理：能力从这个目标中出现，是被实验反复观察到的事实，但「预测得好是否等于理解」，至今仍有争论（见本章第 7 篇）。

二、预训练：读完整个互联网之后，得到什么？

预训练就是在海量通用文本上执行上面的目标。规模有多大？Llama 3 405B 用了 15.6T 文本 token，预训练算力约 3.8×1025 FLOPs，最多同时使用 1.6 万块 H100；DeepSeek-V3 总参数 671B、每个 token 只激活 37B，读了 14.8T token，完整训练共 278.8 万 H800 GPU 小时。

GPT-3 的论文展示了这个阶段最惊人的副产品：只用「预测下一个 token」训练、把规模推到 1750 亿参数，模型就能在不更新任何参数的情况下，只看提示里的几个例子完成翻译、问答、算术等任务，这叫 in-context learning（上下文学习）。

规模不是拍脑袋定的。Kaplan 等人发现，loss 随参数量、数据量和算力按幂律平稳下降；Chinchilla 进一步指出，在固定算力下，参数量和训练 token 数应同比例扩大。于是「模型多大、喂多少数据」变成了可以先用小模型做实验、再外推预测的工程问题（本章第 4 篇详细展开）。

但预训练的产物有一个明显的问题：它只会续写，不会回答。 你问基座模型「法国的首都是哪里？」，它很可能接着写「德国的首都是哪里？英国的首都是哪里？」，因为网上这类文字常出现在习题列表里。它其实「知道」答案：把问题改写成「问：日本的首都是哪里？答：东京。问：法国的首都是哪里？答：」这种后面通常跟着答案的格式，它就能答对。知识已经在了，缺的是以助手身份回应的行为方式。

三、后训练：三种不同的「老师」

后训练用的数据比预训练少几个数量级，却决定了模型好不好用。可以把它看成先后请来的三位老师，各自用不同方式教学。

第一位老师给示范：监督微调（SFT）。 收集「指令 + 优质回答」的示范，用同样的下一个 token 目标继续训练，但只对回答部分计算损失。对模型来说，对话仍然是一段连续文本，只是用特殊标记分出了系统、用户和助手。InstructGPT 的 SFT 阶段只用了约 1.3 万条训练提示；LIMA 更极端，只用 1000 条精选示范微调 65B 的 LLaMA，就得到了很强的对话表现。作者据此提出「表层对齐假设」：知识和能力几乎都来自预训练，SFT 主要教模型用什么格式和风格作答。

第二位老师只做比较：偏好对齐（RLHF / DPO）。 写高质量示范很贵，而人往往更擅长比较：你未必写得出一首好诗，但给你两首，大概分得出哪首更好。InstructGPT 的做法是三步：让标注员对同一提示的多个回答排序 → 用这些比较训练一个奖励模型 → 用 PPO 强化学习让模型生成高分回答，同时用 KL 惩罚把它拴在 SFT 模型附近。结果很能说明问题：在其人工评测中，1.3B 参数的 InstructGPT 的回答比 175B 的 GPT-3 更受偏好，参数少了 100 多倍。 就「好不好用」而言，后训练可能和规模一样重要。2023 年的 DPO 证明可以跳过奖励模型和在线采样，直接在「较好 / 较差」的回答对上优化，实现简单得多。

但这位老师有盲点。奖励模型只是人类偏好的近似，Karpathy 说 RLHF「只勉强算 RL」：它不像围棋那样有客观输赢，优化久了，模型会找到骗过奖励模型的写法，比如越写越长、越写越空，这叫奖励投机（reward hacking）。

第三位老师只判对错：可验证奖励的强化学习（RLVR）。 数学题可以核对最终答案，代码可以跑测试用例。于是可以让模型自己反复解题，对了给奖励，错了不给，不需要人来比较，也没有奖励模型可以钻空子。DeepSeek-R1 的报告显示，直接在基座模型上这样训练（R1-Zero），AIME 2024 的平均 pass@1 从 15.6% 升到 71.0%（arXiv 初版数据；2025 年发表于 Nature 的版本报告为 77.9%），模型还自发学会了写出更长的推理过程、中途检查、发现问题后回头修正。没有人教它怎么想，只告诉它结果对不对，它却自己摸索出了「多想一会儿」的策略。

三位老师的分工可以总结为一张表：

阶段 数据 学到什么 主要风险
预训练 数万亿 token 的通用文本 语言、知识、潜在能力 只会续写；记住部分原文
SFT 数千到数十万条示范 对话格式、指令遵循 灌不进大量新知识
偏好对齐 人类或 AI 的比较数据 有用、得体、安全 奖励投机、对齐税
RLVR 可自动判分的题目 推理正确率 只覆盖能验证的任务

四、最后两站：评测与部署

评测回答「这个模型能不能上线」。图中列了能力基准、安全与红队、人工盲评三类。它们互相补充：基准便宜但可能被训练数据污染；红队专门找有害输出；人工盲评最接近真实体验，但成本最高。InstructGPT 还记录了一个现象：RLHF 之后，部分公开 NLP 基准的表现会下降，称为「对齐税」，他们通过在 PPO 中混入预训练梯度来缓解。

部署时，推理分为 Prefill（一次性处理整段提示）和 Decode（逐个生成 token）两个阶段。前者计算密集，后者受显存带宽限制；KV Cache 的管理、批处理调度和量化决定了吞吐与成本（本章第 6 篇）。一个常被低估的事实是：模型只训练一次，却要被调用无数次，推理的累计成本经常超过训练，所以 MoE、GQA 这类架构选择很多时候是为推理服务的。

五、对架构师意味着什么？

把这条线看清楚，最直接的价值是判断「一项能力该从哪里来」：

  • 知识和通用能力是「买来的」，主要由预训练（数据 + 规模）决定。绝大多数企业不需要也不应该从头预训练。
  • 格式、语气、领域话术是「调出来的」，提示工程或少量高质量 SFT 就够。
  • 最新或私有的事实是「查出来的」。少量 SFT 主要改变风格，要注入大量新事实，RAG 或继续预训练更可靠。
  • 可验证任务上的正确率是「练出来的」。如果你的任务能写出自动判分规则（单测、校验器），RLVR 是目前最有效的路线；这也解释了为什么代码能力进步得特别快。

最后记住三个常见误解：微调不能稳定地教会模型新知识；RLHF 不是能无限提升的「真正」强化学习；训练完也远没有结束，评测和推理才是长期开销所在。
