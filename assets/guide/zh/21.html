四代工具对比：自主度越高，越依赖自动验证

对应图 #21 · 第三章「编程的进化」

概述

把前几篇的内容放在一起，可以得到四代开发工具：传统 IDE → AI 补全 → AI IDE → Coding Agent。从左到右，AI 承担的工作越来越多，人的介入越来越少；但每多一分自主度，就要多一分自动化验证来兜底。这是本章最重要的结论。

核心机制

代际 AI 做什么 人做什么
传统 IDE 无（静态分析） 全部
AI 补全 预测下一段代码 逐条接受或拒绝
AI IDE 对话、多文件修改 审每个 diff
Coding Agent 读、改、跑、修的闭环 定任务、审 PR

为什么自主度越高越依赖验证？

  • 人工审查的粒度变粗：补全时人看每一行；Agent 时人看整个 PR，甚至只看测试结果和核心逻辑。
  • 错误会累积：Anthropic 指出 Agent 是有状态的，错误会累积；自主性意味着更高成本和错误累积的风险。
  • 验证是 Agent 自我纠错的唯一可靠信号：Anthropic 强调 Agent 每一步都要从环境中获得「真实反馈」。

阿里巴巴《AI Native 研发范式实践手册》（解读版）提出一个规律：AI 总是优先解决那些反馈公开、验证可以规模化的问题，这也是编码最先被解决的原因。

关键论文与里程碑

  • 2021 HumanEval：用单元测试衡量功能正确性
  • 2023 SWE-bench：用仓库原有测试判断 issue 是否被修复
  • 2023 Reflexion：利用测试反馈让 Agent 在下次尝试中改进
  • 2025 DeepSeek-R1：在可验证奖励上做强化学习，代码题用编译器和测试判分

可以看到，从评测到训练再到使用，「可自动验证」贯穿始终。

工程实践与数字

  • 按任务风险选择代际：探索性原型可以让 Agent 高度自主；支付、权限、数据迁移等改错代价高的地方，应降低自主度或加强人工关卡。
  • 先补验证，再提自主度：没有测试的模块，先让 Agent 补测试，再让它改功能。
  • 验证要覆盖真实路径：前述 X 上的开发者经验是，单元测试写得再多，上线仍可能出错；关键是为 Agent 提供端到端的测试环境，让它能从真实入口执行到用户需要的结果，并能查库表和日志。

常见误区

  • 「最新一代工具一定最好。」 合适的代际取决于任务和验证条件。
  • 「有 Code Review 就够了。」 人的审阅难以覆盖 Agent 的产出速度，需要机器先把关（见第四章「分层验证」）。
