预训练与规模定律：预测下一个 token，规模按幂律换来更低 loss

对应图 #6 · 第一章「大模型如何训练」

预训练是整条流水线里最贵的一步。一次前沿规模的训练要占用上万块 GPU、持续数月，几乎没有「试错重来」的余地。那么，在按下开始键之前，团队怎么决定模型做多大、喂多少数据、预期能达到什么水平？图 #6 给出了答案的骨架：训练目标是下一个 token 的交叉熵；loss 曲线在双对数坐标下近似一条直线；Chinchilla 给出了「约 20 个 token 对应 1 个参数」的配比；而 C≈6ND 把参数量、数据量和算力串在了一起。这篇文章按工程决策的顺序把它们讲清楚。

一、先把账算对：C≈6ND 从哪里来？

设模型有 N 个参数，训练读 D 个 token。一个 token 前向经过模型时，每个参数大约参与一次乘法和一次加法，约 2N 次浮点运算；反向传播要算对激活和对参数的两份梯度，约是前向的两倍，即 4N。合起来每个 token 约 6N，总算力：

C≈6ND

这个近似在 Kaplan 等人的规模定律论文里给出（只计非嵌入参数），简单到可以心算，却非常准。代入 GPT-3：6×1.75×1011×3×1011≈3.15×1023 FLOPs，论文报告的是 3.14×1023。再代入 Llama 3 405B：6×4.05×1011×1.56×1013≈3.8×1025，与报告的 3.8×1025 FLOPs 吻合。有了这个式子，任何「模型多大 × 读多少」的方案都能马上换算成算力，再换算成 GPU 小时和钱（本章第 8 篇）。

二、幂律：loss 为什么是一条直线？

Kaplan 等人 2020 年系统测量了交叉熵与规模的关系，发现在跨越七个数量级以上的范围内，测试 loss 随参数量 N、数据量 D、算力 C 平滑地按幂律下降：

L(N)=(NNc​​)αN​, αN​≈0.076;L(D)=(DDc​​)αD​, αD​≈0.095

幂律在双对数坐标下是一条直线，这就是图中那条曲线的含义。指数很小意味着什么？算一下就清楚：参数量扩大 10 倍，loss 变为原来的 10−0.076≈84%；数据量扩大 10 倍，变为约 80%；在最优分配下算力扩大 10 倍，只变为约 89%。

这带来两个直接后果。第一，可预测：先用一批便宜的小模型做实验，拟合出直线再外推，就能预测大模型大约能达到多低的 loss，再决定投入多少资源。Llama 3 正是在自己的数据上拟合规模定律，确定了 405B 这个尺寸在其预算下约为算力最优。第二，要明显变好，规模就得涨好几个数量级。每扩大 10 倍只降一小截，这就是模型越做越大的根本原因。Kaplan 还发现，在较宽范围内，宽度和深度等结构细节对 loss 影响很小，规模本身才是主角。

三、Chinchilla：钱该花在参数上，还是数据上？

固定算力 C 之后，N 和 D 此消彼长：模型大一点，就只能少读一点。Kaplan 的结论倾向于训练很大的模型、数据相对少、远在收敛前停下。2022 年 DeepMind 的 Chinchilla 研究重新做了这个实验：训练 400 多个模型（7000 万到 160 亿以上参数、50 亿到 5000 亿 token），拟合出一个把 loss 拆成三项的公式：

L(N,D)=E+N0.34A​+D0.28B​,E=1.69, A=406.4, B=410.7

三项各有含义：E 是不可约的部分，对应自然文本本身的熵，再大的模型也消除不了；第二项是「模型不够大」带来的损失；第三项是「数据不够多」带来的损失。在固定算力下最小化这个式子，得到的结论是：参数量和训练 token 数应该同比例扩大，模型翻一倍，数据也该翻一倍。

他们据此用和 2800 亿参数的 Gopher 相同的算力，训练了只有 700 亿参数、但读了 1.4 万亿 token 的 Chinchilla。结果 Chinchilla 在大量下游任务上全面胜出，MMLU 平均 67.5%，比 Gopher 高出 7 个百分点以上。1.4T ÷ 70B = 20，这就是「约 20 token / 参数」这个经验配比的来源，也揭示了当时的大模型普遍「训练不足」。

为什么两项研究结论不同？Chinchilla 论文认为，差异部分源于 Kaplan 的实验对所有模型使用了固定的学习率调度和训练 token 数，导致小数据量下的大模型被高估。工程上更重要的教训是：配比依赖于你的数据和训练设置，应在自己的数据上重新拟合，而不是照搬一个数字。

四、为什么今天的模型常常「超量训练」？

如果 20 token/参数是最优的，为什么 Llama 3 的 8B 模型读了约 15 万亿 token，远超这个比例？

因为 Chinchilla 只优化了一件事：训练算力。可模型只训练一次，却要被调用无数次，每次推理的成本取决于参数量。用更多数据训练一个更小的模型，训练时多花一些算力，换来的是部署后每次请求都更便宜、更快。Chinchilla 论文本身也指出，更小的模型让微调和推理都更省。所以「最优」取决于你优化的目标：如果模型要服务海量请求，超量训练小模型往往更划算。

五、loss 会降到零吗？

不会，这要回到信息论。交叉熵衡量「按模型的估计编码真实文本要花多少 bit」，它永远不低于文本本身的熵：作者下一句想写什么、一个人叫什么名字、明天的新闻是什么，本来就有真正的随机性。Chinchilla 拟合出的 E=1.69（单位是 nat/token，约 2.4 bit）正是对这部分的估计。规模定律描述的，就是模型的交叉熵如何一步步逼近语言本身的熵，也就是香农当年想测量的那个数。（这个数按 token 计算，依赖于数据集和分词方式，不能和香农按字母估算的数值直接比较。）

六、千亿参数怎么装进集群？

当模型大到单卡放不下，训练就变成了分布式系统问题。Megatron-LM 把三种并行组合起来：数据并行（每组 GPU 处理不同的数据批次）、张量并行（把一层的矩阵切到多张卡上）、流水线并行（把不同的层放在不同的卡上，像流水线一样传递）。ZeRO 进一步把优化器状态、梯度和参数切分到各数据并行进程，消除冗余副本，节省大量显存。这些技术决定了上万块 GPU 能否被有效利用，也直接影响最终账单。

七、容易误读的三件事

「涌现能力是突变。」 Wei 等人记录了一些在小模型上不出现、在大模型上突然出现的能力。但 Schaeffer 等人指出，很多「突变」源于评测指标不连续（比如只看完全答对）；换成连续指标后，曲线变得平滑且可预测。两种观点都有证据，关键是看清用的是什么指标。

「规模定律保证下游能力。」 幂律描述的是交叉熵 loss。下游任务分数与 loss 的关系要另行评估，不同任务的敏感程度差别很大。

「大就是好。」 规模定律说的是「在其他条件相同时」。数据质量、配比、训练设置一变，曲线就会移动。FineWeb-Edu 的例子说明，更好的数据相当于把整条直线往下平移。
