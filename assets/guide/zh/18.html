传统 IDE：工具集成在一起，串联仍然靠人

对应图 #18 · 第三章「编程的进化」

图 #18 画的是一个传统 IDE 的结构：项目结构、代码编辑器、终端与构建、调试与测试、Git 版本控制，五个模块围绕着中间那个橙色的椭圆「开发者（人）」，箭头上标着「手动切换」。下方是一次需求的典型流程：找到相关文件 → 改代码 → 构建 → 跑测试 / 调试 → 提交 Git。底部一句话点题：工作对象是「文件」，人负责串联一切。

这张图在本章里扮演「基线」的角色。要理解 AI 工具改变了什么，先要看清 AI 之前，开发者的时间和注意力到底花在了哪里。

一、IDE 解决了什么问题？

在 IDE 出现之前，开发者用的是一组独立工具：vi 或 Emacs 写代码，GCC 编译，make 构建，GDB 调试。每个工具都很强，但它们之间没有共享的上下文：编译器报了第 42 行错误，你要自己切到编辑器、找到那一行；调试器停在某个断点，你要自己记住刚才看的变量。

IDE 的初衷，是把这些原本分散的工具放进一个界面，提供一致的体验。今天成熟的 IDE 已经集成了代码导航、重构、静态检查、测试运行、版本控制和终端。点一下编译错误就跳到对应行；在编辑器里直接设断点；在侧边栏看 Git diff。IDE 消灭的是工具之间的物理切换成本。

二、静态分析：准确，但只懂「结构」

传统 IDE 的「智能」来自静态分析：解析源代码，构建语法树和符号表，从中回答问题。

  • 补全：光标处可以调用哪些方法？
  • 跳转定义 / 查找引用：这个函数在哪里定义、被谁调用？
  • 安全重构：把这个方法改名，所有调用处一起改。
  • 静态检查：这里可能有空指针，那个变量从未使用。

这些能力有一个共同特点：准确、确定、可解释。 重构改名不会漏掉任何一处调用，因为它基于对代码结构的完整解析。这恰恰是 AI 时代仍然需要它们的原因（见第五节）。

但静态分析只能回答「代码的结构是什么」，无法回答「这次需求要改什么」。它不知道「用户反馈头像上传失败」对应的是哪几个文件，也不知道修复应该放在网关、应用层还是存储层。从需求到代码的那一跳，完全靠人。

三、人是工作流的调度器

看一次典型的缺陷修复流程，把每一步是谁在做标出来：

  1. 理解问题描述，在脑中形成假设。（人）
  2. 定位相关代码：搜索关键词、跳转定义、读调用链。（人用工具）
  3. 修改代码。（人，IDE 补全辅助）
  4. 运行测试，阅读失败信息。（人触发，人读）
  5. 必要时启动调试器、查看日志，修正假设。（人）
  6. 重复 3–5 直到通过。（人决定何时停止）
  7. 提交、推送、等 CI，处理代码评审意见。（人）

每一个工具都只做了自己那一小段；步骤之间的衔接、判断和上下文传递，全部由人完成：看到测试失败，判断是代码错了还是测试错了；看到日志里的异常，联想到三天前改过的那个配置；决定现在该去调试，还是该去问同事。

这种串联有两项隐性成本。一是注意力切换：在编辑器、终端、浏览器、日志系统之间来回跳，每次切换都要重新加载上下文。二是等待：等构建、等测试、等 CI、等评审，人在等待时很难做别的深度工作。工具越多，衔接和切换的负担越重，瓶颈在串联，而不在任何单个工具。

四、AI 工具切入的顺序

理解了这张基线图，就能理解后面几代 AI 工具的切入顺序：

  • 先自动化「写」：Copilot 和 AI IDE 首先替代的是第 3 步，人在编辑器里少敲很多字。但第 1、2、4–7 步仍然靠人串联。
  • 再自动化「串」：Coding Agent 把第 2–6 步变成一个由模型驱动的循环：自己搜索、自己改、自己跑测试、自己读报错、自己决定下一步。人只保留第 1 步（定义任务）和第 7 步（审阅结果）。

这也解释了一个常见的体感差异：AI 补全让人「打字更快」，但未必让需求「交付更快」，因为串联的成本没有变；Agent 才真正开始触碰串联本身。

五、传统 IDE 在 AI 时代的位置

确定性工具恰好是 Agent 最需要的。 Agent 自己是概率性的，它需要可靠的外部工具来校验自己：编译器告诉它语法对不对，类型检查告诉它接口对不对，测试告诉它行为对不对，调试器和日志告诉它运行时发生了什么。SWE-agent 的研究发现，为 Agent 专门设计的接口（查看、搜索、编辑文件和运行测试的命令）能显著提升它解决真实 issue 的能力。传统 IDE 的这些能力，在 Agent 时代从「给人用的界面」变成了「给 Agent 用的工具」。

协议也一脉相承。 Language Server Protocol（LSP）标准化了编程语言支持接入各种开发工具的方式，让同一个语言服务器可以服务所有编辑器。上一章讲的 MCP 规范明确以 LSP 为参照，把同样的思路用在了 AI 应用接入工具上。

很多 AI IDE 本身就建在传统编辑器之上。 它们继承了成熟的编辑、调试和插件生态，再在上面叠加 AI 能力。

六、常见误解

  • 「IDE 已经过时。」 Agent 调用的仍然是同样的编译、测试和调试工具，只是调用者从人变成了模型。
  • 「工具越多效率越高。」 工具多了，衔接和上下文切换的负担也更重。瓶颈在串联，而不是单个工具。
  • 「AI 补全解决了效率问题。」 补全只加速了「写」这一步，串联和等待的成本还在。
