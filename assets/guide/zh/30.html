Orca：一个任务一个 worktree，一个 worktree 一个 Agent

对应图 #30 · 第五章「多 Agent 编程」

概述

多个 Agent 同时改同一份代码，最先遇到的问题是互相踩踏：一个 Agent 改的文件被另一个覆盖，切分支会打断正在运行的任务。Git worktree 是解决这个问题的基础设施，Orca 则是围绕它构建的多 Agent 开发工作台。Orca 官方文档的定位是：一个让多个 AI 编程 Agent 并排运行的桌面 IDE，每个任务有自己的 git worktree、自己的 Agent 终端和自己的浏览器标签页。

核心机制

1. Git worktree。 Git 官方文档说明，一个仓库可以支持多个工作树，从而同时检出多个分支；新建的工作树称为「linked worktree」，与 git init 或 git clone 创建的主工作树相对。所有工作树共享同一个仓库的对象和历史，但各自有独立的工作目录和检出分支。

git worktree add ../fix-payment -b fix-payment
git worktree list
git worktree remove ../fix-payment

2. Orca 的模型。 官方文档把工作流压缩成：添加仓库 → 开工作区（worktree）→ 选 Agent → 分屏 → 看改动 → 提交。要点：

  • 不自带模型：运行你已有的 Claude Code、Codex、Cursor CLI、OpenCode 等，用你自己的订阅。
  • 每个 worktree 都是真实的 git worktree，可以随时进入目录用原生 git。
  • 默认在本地桌面运行，远程计算使用你自己控制的机器（SSH、自托管服务器或云 VM）。

3. 让新 worktree 一进门就能干活。 新的 worktree 是从 Git 检出的干净代码，未被 Git 管理的 .env、依赖目录都不在里面。前述 X 上的开发者介绍，Orca 可以配置哪些文件为每个副本复制一份（如 .env）、哪些目录共享一份（如依赖包）。

4. 共享规则。 项目规则靠 Agent 自己会读的文件：Claude Code 读 CLAUDE.md，Codex 读 AGENTS.md。必须提交到 Git，否则新 worktree 中的 Agent 看不到。

工程实践与数字

  • 通知与审阅：据前述开发者介绍，Agent 从干活变为空闲时 Orca 会弹通知；改动视图支持逐行批注并一次发回给 Agent，还能标出哪些行是 AI 写的。
  • 任务命名：一个 worktree 对应一个明确的任务和分支，便于事后清理。
  • 用完即删：落选或完成的 worktree 及其分支要及时清理。
  • 适用边界：该开发者坦言，如果只用一家的 Agent、一次只做一件事，Orca 帮不上太多忙，官方客户端就够了；它的价值与同时运行的 Agent 数量和需要验收的改动量成正比。

常见误区

  • 「多开几个终端也一样。」 可以，但缺依赖、盯不过来、审不过来这些问题需要自己解决。
  • 「worktree 之间完全隔离。」 它们共享仓库历史和对象库；端口、数据库、外部服务等运行时资源仍可能冲突。
  • 「Orca 是一个模型或托管服务。」 官方文档明确说明它不是模型，也不是托管的 VPS 产品。
