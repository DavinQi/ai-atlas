多人 + 多 Agent：人定义与审阅，数字员工执行

对应图 #34 · 第五章「多 Agent 编程」

当不只一个人、而是一个团队同时与多个 Agent 协作时，问题就从工具变成了组织：谁定义任务？谁审阅？Agent 的身份和权限如何管理？阿里巴巴实践手册中的 AIDC 数字投手团队，经历了「超级个体 → 数字员工 → 云上 Scrum」三个时期，是回答这些问题的一个真实样本。这一篇沿着这个团队的经历来讲。

一、第一阶段：超级个体

据手册记录，团队统一使用一款主流 Agent 工具后，单人指挥 3～5 个会话工作成为常态，夜间也能完成部分长程任务，体感上一人能干两到三人的活，帮助团队完成了首版 MVP。

听起来很美好，但很快出现了两类问题：

  • 消化障碍。 消耗大量 token 产出的中间产物，理解、评审和应用很难靠人完成。和同事沟通方案时，同事也讲不清设计，只能把问题抛给 Agent。
  • 复用障碍。 一个任务交付后，经验很难被他人复用。

这两个问题的根源是同一个：产出和理解脱节了。 过去，一个人写的代码，他自己一定懂；现在，一个人「指挥」出来的代码，他自己也未必完全懂。团队里每个人都成了超级个体，但个体之间的知识没有流动起来。规模越大，这个问题越严重。

二、第二阶段：把 Agent 当作「数字员工」

从「人有没有权限」到「谁在以谁的名义做什么」。 手册把 Agent 视为企业系统中的独立行动主体。平台过去只需回答「这个人有没有权限」；现在必须回答：哪个 Agent、在什么运行时、代表哪个用户、基于哪个任务、访问哪个资源、做什么动作、是否需要人批准。

为什么不能直接用人的账号？手册分析：复用人的账号，审计时分不清是人还是 Agent 操作的；复用服务账号，又看不清谁负责、谁授权、谁能停用。设想某天凌晨，一条生产配置被修改了。如果日志里只记着「张三」，你无法知道这是张三本人改的，还是张三的某个 Agent 在执行某个任务时改的，更不知道是哪个任务。

信任边界的外移。 手册把人与 Agent 的协同大致分成三个阶段，本质上是信任边界不断外移：

阶段 信任边界 人的职责
本地辅助 人 + 本地工具 提供上下文、批准命令、检查结果
云端自主 人 + 云端运行时 + 仓库 设定目标、检查 MR、关键审批
多 Agent 团队 主 Agent + 专家 Agent + 多系统 设计协作流程、治理边界、承担最终责任

从上往下，人做的事越来越少地涉及具体操作，越来越多地涉及规则和责任。

「实习生」比喻只能用一半。 手册提醒，用「实习生」理解 Agent 只能用一半：Agent 确实需要导师、职责、权限边界和 Review，但它没有职业伦理和隐含常识。一个人类实习生即使没人告诉他，也知道不该删生产数据库；Agent 不一定知道。所以治理还要靠机器可执行的护栏，这与第二章介绍的 OWASP 建议（高风险操作须人工批准、最小权限）和 MCP 规范（工具调用前须获得用户明确同意）一脉相承。

三、职责重新划分

数字投手团队得出的分工是：

  • 系统负责状态、权限、规则等高确定性事务；
  • AI 负责分析、生成和跨步骤的长程执行；
  • 人负责目标设定、关键决策、风险取舍和最终责任。

交付单元也随之改变：从「人和人协作完成任务」，转向「人定义目标与验收标准，数字员工分工执行」。

这个三分法很有启发性：它没有简单地说「AI 做执行、人做决策」，而是把系统单独拎了出来。权限检查、状态流转这类事情，交给确定性的代码，比交给 AI 更可靠。这又回到了第三章的结论：概率性的 AI 需要确定性的工具兜底。

四、第三阶段：云上 Scrum

为了解决第一阶段的「复用障碍」，手册中的团队建了两条「云上 Scrum」供给线：

  • 经验 Loop：由两个数字员工分别负责发现和上线策略，策略交付周期从约 10 天缩短至 2 天。
  • 手脚 Loop：把线上失败轨迹转化为能力建设需求，约 80% 的核心能力实现了 Skill 化。

「手脚 Loop」的思路尤其值得借鉴：Agent 失败的地方，就是下一个该建设的能力。 失败轨迹不是被丢弃的日志，而是能力建设的需求来源。这和第四章的「Agent 反复犯错就补一条规则」「重复三次就写成 Skill」是同一个思路，只是从个人习惯升级成了团队流程。

五、数字员工的边界

手册对边界的描述很清醒：增长机会的发现仍高度依赖人的业务理解；目标设定、业务门槛、发布门禁和高风险决策仍需人来承担。数字员工更适合高质量地执行那些已经被想清楚、形成了明确标准的工作。

审阅仍然是团队级的瓶颈。X 上的开发者经验是：保持每个 MR 足够小，人工 Review 聚焦在业务逻辑，以及测试结果是否足以支撑交付。

六、常见误区

  • 「Agent 越多，需要的人越少。」 定义、审阅和治理的工作量会随 Agent 数量上升。
  • 「用个人账号跑 Agent 最方便。」 审计和责任会变得模糊。
  • 「数字员工能替代组织共识。」 它更适合执行已经想清楚的事，而不能替团队把事情想清楚。
