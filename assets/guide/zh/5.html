Transformer：注意力让每个 token 按相关性汇聚上下文

对应图 #5 · 第一章「大模型如何训练」

看两句话：「他口渴了，于是喝了一杯____」和「他困了，于是喝了一杯____」。第一句多半填「水」，第二句更可能是「茶」或「咖啡」。可在「一杯」这个位置上，决定答案的「口渴」和「困」在好几个 token 之前。再看：「奖杯放不进箱子，因为它太大了」里的「它」指奖杯；把「大」改成「小」，「它」就指箱子。

这两个例子说明了语言建模最核心的需求：每个位置都必须能从前文的其他位置有选择地收集信息，而且「收集什么」要随上下文改变。 2017 年的《Attention Is All You Need》给出的答案是 Transformer：去掉循环和卷积，完全用注意力建模序列。今天的 LLM 基本都是它的仅解码器（decoder-only）变体。图 #5 画的就是这样一层：嵌入 → 带掩码的多头自注意力 → 残差与归一化 → 前馈网络 → 残差与归一化，再堆叠 N 层，最后输出下一个 token 的概率。

一、注意力在做什么：一次小型检索

最笨的办法是把前文所有位置的向量平均一下。但这样「口渴」和「了」「，」「于是」分量一样重，有用的信息被冲淡了。注意力把平均变成加权平均，权重由相关程度决定。它像在图书馆找书，每个位置都从自己的向量算出三样东西：

名称 直观含义 图书馆类比
查询 Q 我在找什么信息？ 你想查的主题
键 K 我这里有什么信息？ 书脊上的标签
值 V 如果你关注我，我能提供什么？ 书的正文

Q=XWQ​, K=XWK​, V=XWV​，三个矩阵都是训练出来的。计算分三步：用当前位置的查询和每个可见位置的键做点积得到分数；用 softmax 把分数变成和为 1 的权重；按权重对值加权平均。写成矩阵就是一行：

Attention(Q,K,V)=softmax(dk​​QK⊤​+M)V

手算一次。 前文是「他 口渴 喝了 一杯」，要为「一杯」收集信息。假设向量只有两维，第 1 维大致表示「和饮水有关」，第 2 维表示「指人物」（这是教学构造，真实模型的维度不能这样解释）。各位置的键依次是 (0,2)、(2,0)、(1.5,0)、(0.5,0)，值是 (0,1)、(1,0)、(0.8,0)、(0.3,0)。「一杯」的查询是 (1,0)，意思是「我在找和饮水有关的信息」。

  • 点积分数：他 0，口渴 2，喝了 1.5，一杯 0.5。
  • softmax 权重：e0:e2:e1.5:e0.5≈1:7.39:4.48:1.65，归一化后约为 6.9%、50.9%、30.9%、11.4%。
  • 加权平均：第 1 维 ≈0.509×1+0.309×0.8+0.114×0.3≈0.79，第 2 维 ≈0.069。

「一杯」收集到的信息主要来自「口渴」和「喝了」，「和饮水有关」这一维很强，预测「水」就容易多了。没有人规定「应该关注口渴」：是这样关注有助于降低交叉熵，相应的 WQ​、WK​ 才在训练中逐渐形成。

为什么要除以 dk​​？ 维度越高，点积是越多项相加，数值越大。分数差距太大时，softmax 会把几乎全部权重给一个位置，梯度也会变得很小。缩放让分布保持平缓。

因果掩码 M。 生成时模型只知道已经写出的内容，训练时也必须一致：每个位置只能看自己和前面的位置。做法是把未来位置的分数设为 −∞，softmax 之后权重为 0。这带来一个关键的效率优势：一段 1000 个 token 的文本只需前向计算一次，每个位置都同时在预测自己的下一个 token，相当于一次提供约 1000 道练习题。这是 Transformer 能在 GPU 上高效并行训练的根本原因。

二、多头：同时问几种问题

一句话里同时存在多种关系：谁做了什么、词语搭配、指代、话题。一组 Q/K/V 只能按一种方式查找。上面的例子里，如果把「一杯」的查询换成 (0,1)，意思是「这件事是谁做的」，注意力就会集中到「他」身上。所以 Transformer 把 d 维拆成 h 个头，各自计算注意力后拼接，再用一个矩阵混合。

研究者在真实模型里找到过一些功能清晰的头。例如归纳头（induction head）：前文出现过「A B」，之后再遇到「A」时，它会关注上次「A」后面的「B」，从而预测「B」。Olsson 等人认为这类头是模型能从提示里「现学」规律的重要机制之一。但大多数头的功能并没有这么整齐可读，这也是为什么「注意力权重就是模型的解释」这个说法站不住脚。

KV 头可以共享。 解码时每一步都要读取所有历史位置的 K/V，头越多，读得越多。多查询注意力（MQA）让所有 query 头共享一组 K/V，大幅加速解码；分组查询注意力（GQA）折中为若干组共享，质量接近多头、速度接近 MQA。Llama 3 的 8B、70B、405B 都只用 8 个 KV 头，KV Cache 因此缩小为 nkv​/nheads​（第 6 篇会算具体数字）。

三、前馈网络：回到工位各自消化

注意力完成的是「位置之间交换信息」，像开会；之后每个位置还要各自经过一个前馈网络（FFN），像会后回到工位各自消化。FFN 先把向量放大到约 4 倍宽，经过非线性函数，再压回原宽度。注意力主要在做加权平均，真正做复杂非线性变换的主要是 FFN。

FFN 也是参数的大头。设宽度为 d，一层注意力有 Q、K、V、输出 4 个 d×d 矩阵，约 4d2；FFN 有 d→4d 和 4d→d 两个矩阵，约 8d2，合计约 12d2。代入 GPT-3 的 d=12288、96 层：每层约 18.1 亿，96 层约 1739 亿，加上约 6.2 亿的嵌入表，合计约 1746 亿，和公布的 1750 亿几乎一致。FFN 约占三分之二。 Geva 等人发现 FFN 的行为类似「键-值记忆」：一部分参数识别输入里的模式，另一部分据此提高某些后续 token 的概率。但知识分散在大量参数里，不能指着某个参数说「这里存着巴黎是法国首都」。

四、让几十层叠得起来：残差与归一化

每个子层外面都套着残差连接：x←x+子层(Norm(x))。可以把它想成一条贯穿全模型的「残差流」，每层只往上面写增量，原有信息不会被覆盖，梯度也能直接回传到底层。归一化放在子层之前（Pre-Norm），训练比原版放在残差之后更稳定。

相对 2017 年的原版，现代 LLM 还普遍换了几个组件：

  • RMSNorm：只做均方根缩放，不减均值，计算更省，效果相当。
  • SwiGLU FFN：带门控的线性单元变体，在相同计算量下效果更好。
  • RoPE 位置编码：让注意力分数只依赖相对位置（见上一篇）。

Llama 3 是现代稠密 Transformer 的典型样本：8B 为 32 层、隐藏维度 4,096；70B 为 80 层、8,192；405B 为 126 层、16,384。三者都用 SwiGLU、RoPE（θ=500,000）、128K 词表和 8 个 KV 头。

五、平方的代价，以及 FlashAttention

注意力要让每个位置和所有可见位置两两打分，时间和显存都与序列长度成平方关系。上下文从 4K 扩到 128K，长度增加 32 倍，注意力矩阵大约要增加 1000 倍。

FlashAttention 的思路不是改数学，而是改访存。GPU 的计算很快，瓶颈常在高带宽显存（HBM）和片上 SRAM 之间来回搬数据。它把 Q、K、V 分块（tiling）放进 SRAM，在块内算完 softmax 和加权求和再写回，避免把巨大的注意力矩阵写到 HBM。结果与标准注意力完全一致，论文报告在 GPT-2（序列长 1K）上端到端训练提速 3 倍；FlashAttention-2 进一步改进了并行与工作划分。今天 PyTorch 的 SDPA、vLLM 等框架都默认集成了这类内核，自研时应优先复用。

六、三个常见误解

  • 「注意力权重就是模型的解释。」 注意力只反映信息路由的一部分，FFN、残差流和多层组合都参与了决策，不能直接当作因果解释。
  • 「上下文窗口越长，模型都能用上。」 窗口长度是架构和训练的上限，模型实际能否利用远处的信息，需要单独评测。
  • 「FlashAttention 是近似算法。」 它是精确注意力，只是计算顺序和访存方式不同。
