Agent 的组成：LLM + 规划 + 记忆 + 工具，在环境反馈中循环

对应图 #11 · 第二章「Agent 设计原理与范式」

概述

「Agent」一词的定义并不统一。Anthropic 在《Building effective agents》中把所有基于 LLM 的自动化系统统称为 agentic systems，并做了一个关键区分：工作流（workflow）是由预先写好的代码路径编排 LLM 和工具；Agent 则由 LLM 自己动态决定流程和工具调用，自主掌控完成任务的方式。

Lilian Weng 在 2023 年的综述《LLM Powered Autonomous Agents》中给出了被广泛引用的组成框架：LLM 充当 Agent 的「大脑」，配合三个关键组件——规划（Planning）、记忆（Memory）和工具使用（Tool Use）。

核心机制

1. 规划。 把大任务拆成可管理的子目标；并通过自我反思（self-reflection）从过去的行动中总结经验、修正错误。

2. 记忆。 Weng 的划分是：

  • 短期记忆：上下文中的全部内容（in-context learning），受上下文窗口限制。
  • 长期记忆：借助外部向量库和快速检索，在长时间跨度内保存与召回信息。

3. 工具。 调用外部 API 获取模型权重中没有的信息：实时数据、代码执行、私有数据库等。Toolformer 证明模型可以自监督地学会何时、如何调用 API；CodeAct 则提出用可执行的 Python 代码作为统一的动作空间，在其基准上成功率比 JSON / 文本格式的动作最高提升 20%。

4. 环境反馈循环。 Anthropic 强调，Agent 执行时每一步都要从环境中获得「真实反馈」（工具调用结果、代码执行结果）来评估进展，并在检查点或遇到阻碍时停下来等人反馈；同时应设置停止条件（如最大迭代次数）。它们的结论是：Agent 在实现上通常很简单，本质就是 LLM 在循环中根据环境反馈使用工具，因此工具集及其文档的设计至关重要。

CoALA 框架从认知科学角度给出更形式化的描述：模块化的记忆组件、与内部记忆和外部环境交互的结构化动作空间，以及选择动作的通用决策过程。

工程实践与数字

  • 从最简单的方案开始：Anthropic 建议先找最简单的解法，必要时才增加复杂度；很多应用只需优化单次 LLM 调用、配上检索和示例就足够。Agentic 系统通常是用延迟和成本换取更好的任务表现。
  • 框架要慎用：框架会增加抽象层，掩盖底层的提示和响应，增加调试难度。建议先直接调用 LLM API，很多模式几行代码就能实现。
  • 三条原则：保持设计简单；明确展示 Agent 的规划步骤以保证透明度；通过完善的工具文档和测试精心设计 Agent-计算机接口（ACI）。SWE-agent 的研究也表明，专门为 Agent 设计的接口能显著提升其在软件工程任务上的表现。

常见误区

  • 「Agent 就是加了工具的聊天机器人。」 关键差别在于由谁决定控制流：工作流由代码决定，Agent 由模型决定。
  • 「越自主越好。」 自主性意味着更高成本和错误累积的风险，Anthropic 建议在沙箱中充分测试并配备护栏。
  • 「记忆就是把所有历史塞进上下文。」 上下文是短期记忆，长期记忆需要外部存储和检索。
